# 原始材料用户任务观察协议（待执行）

此协议测量普通用户为得到可用建模结果付出的工作，不用外部专家给数学模型打分。当前**尚无真人样本**；网页的 `input_burden` 只是进程内会话计数，不能代替下述观察。

## 任务与参与者

- 先冻结系统版本、任务材料、评分规则和单题时间上限，再邀请未参与开发的人。小规模试点建议覆盖代数/符号、动力学、优化、多表各至少一题；人数和题数仅用于发现流程障碍，不预设统计代表性。
- 每题交付原始题面与附件，不预先改列名、挑目标列或写模型合同。任务若有唯一数值答案，隐藏参考和评分器由组织者保管；开放式题只记录流程与失败分析，不硬算准确率。
- 参与者可自行澄清题意和整理附件，但观察者不得提示应选模型、应改哪列或正确数值。需要协助时记录协助内容与时间，不能仍计作零人工介入。

## 每题记录（包括放弃和系统失败）

| 字段 | 定义 |
| --- | --- |
| `task_id`、`source_group`、`participant_id` | 使用匿名 ID；同源结构变体保持同一组 |
| `start_at`、`end_at` | 从拿到原始材料到提交最终答案/放弃的墙钟时间；含系统等待 |
| `active_minutes` | 观察者用开始/暂停计时记录的实际阅读、整理、输入和检查时间；不含求解等待，不能由 API 时间戳推断 |
| `preparation_minutes`、`field_edits` | 首次提交前的附件整理时间与字段/单位/表关系修改数 |
| `clarification_rounds`、`upload_revisions`、`run_submissions` | 用户回答澄清、补传/改传、重新提交次数；与会话计数核对 |
| `manual_hints`、`abandoned` | 人工提示次数与是否放弃；不能从成功案例中剔除 |
| `result_grade`、`scored_outcome` | 分别保存系统自报等级和独立评分的正确接受/错误接受/正确拒答/错误拒答/未评估 |
| `reason_code` | 失败或拒答原因；保留原始码，汇总时再分类 |

每题开始前用新的浏览器会话；结束后立即读取 `GET /api/research/input-burden` 并保存脱敏计数。现有服务把计数存于进程内，多进程切换或重启可能丢失；观察表是主记录。不要收集 API 密钥、完整题目文本或私人附件内容到汇总表。

## 汇总与边界

主表按任务列出所有尝试，分母包含放弃和失败；分别报告正确接受、错误接受、正确拒答、错误拒答和未评估。输入负担报告 `active_minutes`、总墙钟时间、首次提交前整理时间、澄清轮数、补传次数及重跑次数的中位数与范围。若同一参与者做多题，统计区间按参与者或结构组处理相关性，不把多轮重跑当作独立题。观察后的题目可用于改产品，但随后只能作为开发材料；确认改进必须另留任务与参与者。
