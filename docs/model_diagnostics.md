# 模型诊断与修复方向

研究结果中的诊断面板解释“哪类检查发现了什么、下一步可以检查什么”。它不修改模型，不把诊断建议当作数学结论。

## 当前覆盖

- 积分动力学：训练库冗余、活跃参数秩亏/病态、训练子段支持不稳定、选参段基线、残差偏置、残差时间相关及幅度相关。
- 未闭合系统竞争筛查：把残差记忆、外部输入、异方差、非平稳和整体函数库/数值失配并列展示，避免把高噪声直接命名为隐变量。
- 通用机理求解：结构化超时、内存、定义域、上游失败、收敛检查与契约缺失。
- 假设图：类型拒绝、未填机制、符号和语义待确认。
- 预测模型（回归/分类）的开发段诊断：跨折稳定性、OOF 残差偏差、残差结构、异方差候选和分类错误率；这些信号与动力学诊断共用只读反馈通道。
- 聚类可信度筛查：簇间分离、随机种子稳定性和极小簇警告进入相同反馈通道；簇标签与原始标签均不会被诊断器复制。
- 有序时序结构筛查：当数据结构分析中存在可靠时间列时，周期、变点和单调性候选信号进入相同只读通道；重复时间先聚合，信号不用于证明机制。

候选库存在重复项，不代表已经选中的参数必然不可辨识。残差有相关性，也可能来自观测噪声、时间对齐或积分误差；系统保留这些替代解释。

## 数据边界

`diagnose_development` 只接收训练段与选参段，不接收最终测试数据。残差模式使用非重叠窗口，并且不跨缺口拼接相邻残差。样本不足时保留“未评估”，不制造统计结论。

预测模型诊断只读取服务器生成的 OOF/内层交叉验证标量摘要。原始标签、预测数组、独立确认集和最终测试数组不会进入诊断产物或 `search_feedback`；模型名称和目标名称只作为截断后的审计主题。

时序交叉验证还保存 `CVResult.oof_mask`，只把实际进入验证折的时间点用于残差、共形区间和模型竞争；`TimeSeriesSplit` 的初始训练窗口不会因零初始化而被当成预测结果。旧版没有掩码的序列化结果仅走兼容性降级路径，并应在报告中保留这一限制。

监督模型结果同时保存 `data_split.partition_fingerprint`、划分策略及开发/确认样本数。指纹只由行标识哈希构成，不保存原始行号；它用于复现与发现划分漂移，不等于独立性或无泄漏证明。

最终测试失败可显示在面板，但被隔离在 `search_feedback` 之外。若用户依据最终测试重新建模，需要重新取得独立确认数据；改变文件名或重新点击运行不能使旧测试变得独立。

筛查阈值只是未校准的诊断规则，不是 p 值或显著性检验。当前没有覆盖全部模型族；“未发现问题”只指已执行的检查。

竞争筛查的分数是排序用信号，不是概率；候选接近时网页和报告会保留多个解释。只有补充独立轨迹、观测模型和可辨识性证据后，才允许进入结构搜索或用户确认流程。

## 产物

运行目录的 `evidence/model_diagnostics.json` 使用 `mathmodel.model-diagnostics/v1`。记录包含阶段、输入指纹、检查量、替代解释和白名单行动方向，不含原始报错堆栈。产物角色为 `diagnostic_not_proof`，不能自行提升论证等级。

主实现为 [model_diagnostics.py](../core/model_diagnostics.py)，测试为 [test_model_diagnostics.py](../tests/test_model_diagnostics.py) 和 [网页渲染测试](../tests/test_model_diagnostics_ui.js)。

外部模型入口的 `LLMConfig` 还会在发出请求前检查调用次数、提示体积和输出 token 预算；这只是请求级护栏，不代表供应商账单、网络隔离或模型输出正确性已被系统证明。
