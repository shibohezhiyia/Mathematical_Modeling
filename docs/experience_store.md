# 验证后经验库（初版）

`core.experience_store.ExperienceStore` 为跨运行复用提供一个受限的内容寻址存储。它保存的是“经过脱敏的数学配方和证据元数据”，不是原始数据仓库，也不是可以直接复用的答案。

## 生命周期

1. `put(...)` 以 `provisional` 写入题意契约、IR、执行计划、证书摘要和失败轨迹。对象按脱敏后的 JSON 的 SHA-256 保存，重复内容不会生成第二份对象。
2. `promote_verified(...)` 只有在复现、反例检查、安全检查和非空验证范围全部明确为真时，才允许晋级为 `verified`。验证记录写在索引中，不改变原配方的内容地址。
3. `search(...)` 依据数学图、单位和目标签名计算相似度，不依赖题目文本。返回项始终带 `seed_only=true` 和 `requires_current_validation=true`；调用方必须在当前题目上重新做类型、单位、资源和留出检查。
4. `purge(...)` 默认只清理 `provisional/rejected`，支持按运行、主题或创建时间预览后清理。`verified` 必须给出明确范围，避免误删可信记录。

## 隐私边界

- API key、Bearer token、密码、cookie、私钥等敏感字段替换为 `<redacted-secret>`。
- 原始观测、样本行和记录集合替换为“不持久化原始观测”的占位对象。
- Windows/POSIX 绝对路径替换为 `<redacted-local-path>`。
- 经验库仍可能包含题面语义或模型结构；公开仓库前应审查导出的 recipe，不要把整个工作区直接写入经验库。

这只是 P10 的第一块基础设施：它尚未自动证明复现历史，也没有把搜索器接成“命中即采用”。完整的经验晋级仍需固定版本、独立留出、反例回放和安全测试共同提供证据。
