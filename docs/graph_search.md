# 类型化数学图搜索：可运行的开发切片

此入口让标量数学图经过“原语组合 → 训练段拟合参数 → 历史反例重放 → 开发检查”的闭环。它不依赖题目名称或完整题型模板，但目前不是自动处理任意题面的通用研究系统。

## 快速运行

在项目根目录执行：

```bash
python scripts/run_graph_search.py examples/graph_search_scalar.json
```

[示例](../examples/graph_search_scalar.json) 是明确标注的合成开发实验：初始假设仅为输入的恒等观测，后台从合法原语变化中找到能解释示例数值的组合。生成公式没有写在求解器中；示例数据也不能当成未见题基准或真实世界验证。

结果位于默认被 Git 忽略的 `workspace/graph_search_runs/<run_id>/`：

```text
artifact_manifest.json
evidence/
  search_input.json
  graph_search.json
  counterexamples.json
reports/
  graph_search.md
cache/
temp/
logs/
```

每次创建新运行，不覆盖旧清单。`cache`/`temp` 延用已有的独立清理类别；本切片的中间计算缓存只在 worker 内存中，随进程结束自动释放。输入快照和反例可能包含绑定的用户数据，默认仅保存在本地，不调用模型 API。

## 实验契约

`mathmodel.graph-search-bundle/v1` 包含 `problem`、`experiment`、`candidates`、`budget`，可选 `patches`、`grammar_search` 和来自 `diagnostic_router` 的 `diagnostic_hints`。任何额外执行权限或最终测试字段都会被拒绝。

当候选通过搜索分区检查时，评估器还会在报告中保存该分区的
`search_predictions` 与 `search_expected`。它们只属于与训练分区互斥的开发证据，
用于后续候选比较、误差诊断和可视化；最终确认仍必须走独立的 confirmation registry，
不能把搜索分区误称为最终测试集。

`SearchExperiment.create` 提供核心接口：

- `template` 固定符号角色、输出类型和假设；所有可执行节点要求已知单位、实标量类型。
- `domain` 绑定变量的有限区间；输入值按原图声明的单位提供。
- `parameter_bounds` 将参数绑定为 `[下界, 上界, 初始值]`。
- `training_cases` 用于参数拟合；`search_cases` 用于反复检查，不能叫最终测试。
- `properties` 描述输出上下界，必须引用题面上下文或明确假设；来源引用本身不证明语义绑定正确。
- `absolute_tolerance`、`relative_tolerance` 在搜索开始前固定，不允许候选修改。
- `seed`、`probe_count` 确定边界、零点切片和内部抽样；不是对连续域的穷尽证明。

无观测数据时可以检验带来源的条件性质，但不能拟合未知参数或伪造观测真值。当前输入支持最多 8 个变量、8 个参数、4 个输出，训练/选参样本分别最多 256/128；严格 JSON 总规模检查可能进一步限制复杂组合。训练与选参的相同输入会被拒绝，包括整数/浮点数和正负零的不同写法。这是保守的防重叠接口，不适用于未经调整的重复观测设计。

## 求解和修复边界

当前可执行算子为变量、参数、常量、加减乘除、同量纲 `minimum/maximum`、取负、绝对值、平方根、指数、对数、正弦、余弦和恒等观测。积分、微分、未知机制、向量等类型即使能在 IR 表示，也不自动进入这个标量执行器。未知机制可以在其允许的算子范围内填充，填充后仍须重新通过原类型检查。

参数只使用训练样本，由有界局部最小二乘估计。显式设置后端尺度选项，并用独立计数器统计包含数值差分的调用；收敛不等于全局最优，Jacobian 的秩也不自动解释成物理可辨识性。[SciPy least_squares 文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html)

评价器 v2 先从受支持计算图语法证明输出是否对全部参数仿射。证明成立时，以初值及每个参数的一个有界扰动构造训练设计矩阵，调用有界线性最小二乘，记录设计秩；该凸数值子问题的收敛结果仍不是物理可辨识性或形式化全局最优证书。这里没有用浮点近似去猜测线性，也不会把秩亏隐藏起来。

不能证明整体参数仿射时，使用最多三个确定性局部起点：声明初值及其有界正、负偏移。仅按归一化训练 RMSE 选择已收敛结果，不使用选参标签、验收容差或留出数据选择起点。训练残差低于固定 `1e-8` 时提前停止重启；这只是计算策略，不会代替后续严格检查。零梯度和初值定义域失败可以尝试其他起点。当前尚未消去“部分参数线性、部分参数非线性”的混合子块，也不保证找到全局最优。

评价器 v4 对 `a·exp(bx)` 这类结构使用保守的变量投影：根据图语法逐步选择可证明的线性内层参数，在每次外层非线性残差计算时重新做有界线性拟合；内外层的模型评估都计入同一预算。标量图还支持 `abs/sqrt/sin/cos`，其中三角与指数/对数节点强制无量纲，平方根按量纲指数减半。若参数乘积、参数化分母或非线性函数使线性子集不安全，则拒绝投影并回退多起点。报告保存内外层参数清单、投影设计秩和每次尝试，不能把消元结果解释成唯一参数或全局最优。

拟合前为训练回算、历史反例、选参样本和探针预留最坏情况下的批量失败后逐点回退次数；预算不足时报告 `fit_budget_exhausted`，不跳过检查或生成数学反例。每个起点的初值、实际评估次数、配额、训练误差和入选记录保存在开发证据的 `fit.attempts` 中，有限差分及失败调用也计数。后续起点耗尽配额时，保留之前已收敛的拟合供独立检查，而不是自动判定通过。该预留仅限单候选开发 worker，不代表跨阶段总预算已完成。

内置结构变异是小型、确定性的语法搜索基线。它根据数值失败和已审计的诊断提示调整合法算子的尝试顺序，也允许外部提交有父版本指纹的 JSON patch；提示只映射到封闭的原语 ID，不能执行文本、改变硬约束或绕过验证。当前仍没有外部 API 驱动的多轮变异，也没有自动增加潜状态、修改变量语义或修订题意。

### 代数等价与伪多样性

搜索会为交换运算 `add`、`multiply`、`minimum` 和 `maximum` 计算独立的代数等价键，并在入队前折叠仅交换输入顺序的图。这样同一个机制不会因为节点编号或重写标签不同而重复消耗候选预算。`commutative_rewrites` 仍可生成带来源哈希、目标哈希和规则的审计记录，供证据账本说明“这是等价表达，不是新机制”。

该规则只覆盖交换律；它不把结合律、分配律、微积分变换或参数重命名自动判为等价。浮点运算的重排也只记录为“容差内可能等价”，不会声称逐位相同。后续扩大重写集时必须同步保留定义域、边界条件和数值误差义务。

结果还带有 `diversity_audit`：它会在忽略符号名称后报告相同算子拓扑的候选聚集，用来识别变量改名造成的伪多样性。该审计只诊断、不自动删除候选；没有描述符来源时，两个不同字段也可能具有相同拓扑，必须由上层语义绑定继续区分。

每个 patch 最多修改 4 个节点；不能改事实、数据、输出接口、符号、假设、既有节点类型或验收阈值。旧反例始终保留，并在检查新候选前重放。新增反例影响早先候选时，必须复检；容量或时间不足只能报告待验证，不能将未检查候选提升为可信结论。

## 预算、结果和缓存

默认最多 8 次候选数值执行、32 次 patch 尝试、2,000 次图向量评估、单候选 500 次评估和总计 60 秒。错误 patch 也计入尝试预算；无法回收计数的 worker 失败按本次配额保守扣减。单次结果最多保留 64 条反例、会话最多 128 条；达到反例容量时停止搜索，不丢掉旧记录后继续晋级。

标量图通过 `scalar_graph/v1` 接入已有进程监督。没有 `eval`、生成 Python 或任意函数入口；但资源限制仍不是文件/网络权限隔离，详见 [受控数值执行](solver_runtime.md)。

缓存只复用同一图和完全相同有序输入的参数无关中间量，最多 4 个输入批次、2 MiB 数组。参数及其依赖节点每次重算；缓存不存判断结论，不跳过反例或独立检查。`budget.reuse_intermediates=false` 可以关闭复用作对照。当前只验证了结果和检查一致性，以及实际算子计算次数减少；尚未验证端到端提速。跨图增量编译、持久化上下文缓存和多保真晋级仍待完成。

开发结果分为“无候选通过”和“候选待独立确认”。Pareto 比较保留开发误差与图复杂度两个维度，但失败的性质检查不能由较低误差抵消。**开发搜索不接收最终测试数据，也不输出已证正确、因果成立或现实可信的标签。** 单独的冻结留出入口见下节。

## 冻结后执行留出检验

也可使用首页的独立数学图实验面板，按开发和留出两个请求分阶段操作，见 [网页使用说明](graph_lab.md)。该网页入口一次验证一个冻结模型，多策略同预算对照仍使用下方命令行。

开发搜索接口仍不接收最终测试数据。可通过单独的文件入口，在搜索结束并选定模型后进行留出检验：

```bash
python scripts/run_graph_search.py examples/graph_search_scalar.json --confirm examples/graph_search_heldout.json --study scalar_demo
```

命令的顺序是：开发搜索完成 → 选定一个候选 → 冻结图、参数、阈值与证据指纹 → 保存冻结快照 → 首次读取留出文件 → 原子登记样本使用 → 在受控 worker 内评估。留出阶段没有优化器调用，不允许换模型或重新拟合。若有多个 Pareto 候选，先运行不带 `--confirm` 的命令查看指纹，再使用 `--candidate <完整指纹>` 指定；未选定时不会读取留出文件。

新增文件为 `evidence/frozen_model.json`、`heldout_input.json`、`heldout_confirmation.json` 和 `heldout_evidence.json`；原报告同时显示留出状态、RMSE、最大误差和只从训练标签计算的均值基线。开发搜索报告和历史反例不会被留出结果改写。运行状态 `complete` 只表示流程结束，不表示数学问题已经正确解决。

`mathmodel.scalar-holdout/v1` 文件只含 `schema_version` 与 `cases`，每个样本仍使用 `id`、`bindings`、`expected`；最多 256 条，不能额外携带阈值、训练数据或参数。输入点不能与训练、选参、开发探针或同一研究已用留出点重叠。当前这是保守的**精确输入点隔离**，不是时间、实体或近邻相关性隔离，也不证明样本来源无污染或具有代表性。

使用记录保存在默认被 Git 忽略的 `workspace/confirmation/usage.sqlite3`，不属于运行缓存。事务防止并发重复使用；病例 ID、顺序或目标值的改变不会重置输入点。执行超时、取消、资源失败以及进程中断都保留使用记录，不能再次当作新证据。此登记仅覆盖同一 `study` 和同一可信本地登记库；手动删除登记库、改变量语义或另建研究不能被系统识别为真正独立的新实验，不能据此宣称重新验证。

示例是合成数据，不是未见题基准。第二次执行相同 `--study` 和留出样本时，预期会拒绝重复使用；需要查看已有报告，而不是换个名称刷通过。若据留出失败修改了模型，需要另外获取未使用的验证数据。

单模型搜索命令一次只确认一个预选模型。多模型使用 `FrozenModelPanel` 和 `confirm_frozen_panel`：提前冻结 2–4 个模型，要求相同开发实验契约，共用一次留出消费登记，每个模型预分配相同额度，失败也保留，不重试、不转移额度、不根据留出结果选冠军。不能靠给每个候选换 `study` 来冒充独立比较。

面板必须在读取留出数据之前构造；此底层接口检查快照一致性，但不能认证外部调用者的读取历史。相同图可保留不同方法标签。每个 worker 最多 30 秒/1,000 次向量评估，整组最多 4 个 worker 串行执行；额度之和不包含父进程验证与登记开销，不是整组硬墙钟限制。`panel_completed` 仅表示各成员均返回了记录，可能包含验证失败或执行未完成；须查看 `all_arms_passed` 和各成员状态。异常中断会留下已消费的整组登记。

### 整组确认文件入口

在开发过程结束、且尚未查看留出数据时，将各会话的 `session.freeze(candidate_hash)` 快照传入 `FrozenModelPanel.from_models({"baseline": baseline_model, "search": search_model})`，保存其 `public()` JSON 为 `panel.json`。必须使用相同的实验契约；不同方法发现相同模型时可以保留各自标签。此步骤不能先拿最终表现挑模型。

```bash
python scripts/confirm_graph_panel.py panel.json --holdout heldout.json --study comparison_01
```

文件入口先校验并保存整个面板，再首次打开留出文件。默认运行目录为 `workspace/graph_panel_runs/<run_id>/`：

- `evidence/frozen_panel.json`：整组图、参数、开发证据和资源额度。
- `evidence/panel_protocol.json`：研究标识与读取边界说明。
- `evidence/heldout_input.json`：通过格式检查的留出输入。
- `evidence/panel_confirmation.json`：各方法的只读验证结果。
- `reports/panel_confirmation.md`：分方法中文报告。
- `artifact_manifest.json`：文件校验和及运行状态。

完整通过返回退出码 0，有失败/未完成/重复消费返回 1，入口文件或参数校验失败返回 2。输入被拒绝时仍保存冻结快照和拒绝报告；突然中断会保留已写快照、失败清单和持久消费记录，但不保证导出中断前的部分成员结果。更换输出目录不会重置研究登记。外部快照的真实性、生成期间是否看过留出数据仍不能认证。

### 同开发预算的策略对照

现在可以直接使用一个开发实验文件运行对照，无需手工拼装冻结面板：

```bash
python scripts/benchmark_graph_search.py examples/graph_search_scalar.json --holdout examples/graph_search_heldout.json --study scalar_comparison --compare-cache
```

固定对照为不变异的 `fixed_structure`、开启原语语法搜索的 `grammar_search`；`--compare-cache` 额外加入 `grammar_no_cache`。三者共享题意、初始候选、开发数据、阈值、种子和候选/评估/时间上限。该命令明确覆盖输入文件的单策略 `grammar_search` 和缓存开关；不接受额外 patch。上限相同不要求用满额度，剩余额度不转给其他策略。

各方法完成开发后，按预登记的“Pareto 候选中节点最少 → 开发 RMSE 最小 → 指纹排序”选定一个模型。先保存所有方法的结果与冻结选择，再读取留出数据；无可选模型的方法也留在对照分母中。只有一个方法产出候选时走单模型登记，多个时走整组登记，全部失败或已取消时不读取留出文件。固定规则不是题意正确性的证明，也不是对所有问题都最优的选模准则。

默认输出 `workspace/graph_benchmarks/<run_id>/`，包含 `benchmark_input.json`、`benchmark_protocol.json`、逐方法 `development_<index>.json`、`frozen_selection.json`、适用时的留出输入/确认结果，以及 `reports/benchmark.md`。成功运行的汇总显示每方法的开发耗时、计费评估次数、候选数和留出状态。模型 API 调用及费用为 0；峰值内存和首次有效结果耗时仍为 `null`，不伪填零。完整流程退出码 0 要求所有方法通过；有失败方法返回 1，入口格式错误返回 2。带 `--compare-cache` 的示例包含固定结构、通用搜索、诊断搜索和无缓存搜索四个方法，通常为 3/4 方法通过；这是合成流程测试，不是覆盖率实验。

统计显著性、预登记题集、随机种子重复、执行顺序随机化和噪声控制仍待实现。方法执行顺序固定，不能把单次耗时差直接解释为提速。开发搜索默认每方法 60 秒，留出 worker 另设每方法 30 秒/1,000 次评估；统一总预算和预留确认资源仍属于 N08 待办。旧数据换 `study` 也不会重新独立，重复运行请查看已有报告而不是刷分。

核心入口为 [冻结模型与留出评价](../core/graph_confirmation.py)、[使用登记](../core/confirmation_registry.py)。`FrozenGraphModel.from_payload` 检查结构和指纹一致性，不认证外部文件作者；正式路径使用会话私有结果冻结，返回字典被修改不会改变冻结对象。数值 worker 的有限检查本身不是对外部数据来源的认证。
