## 实施顺序、交付物与完成门槛

1. 完成 R0 和 R9 清点，审计 R7 现有通道；优先处理误删、数据泄漏及固定模型排序。
2. 用已有数值后端实现 R1 的最小主流程；每个新增适配器都同时补运行结果与失败路径。
3. 接通 R3、R4，使开发证据能改变下一轮结构/参数选择；保留锁定确认预算。
4. 按真实失败归因扩展 R2.1–R2.4，各后端独立验收；再接 R6 与 R8。
5. R5 的协议设计贯穿以上阶段，功能稳定后冻结版本做最终比较和独立评分。

每项交付包含代码变更、主入口运行例、失败例、测试结果及未支持条件。每次研究的 IR、绑定、求解记录、诊断、反例、确认、判决均归入同一个版本化运行目录，沿用现有 artifact manager；可再生缓存与正式证据分开，产物清单记录路径、哈希、用途和清理范围。

效率优先级：按需导入 → 有界数据视图与批量数值运算 → 类型/单位早拒绝 → 候选去重 → 分级计算与缓存 → 自适应预算。每步比较同预算下的有效解、错误接受、P50/P95 延迟、峰值内存及费用，不能因减少最终验证而报告提速。

勾选完成须同时满足：约定用户入口可达、实际数值运行、必要检查通过、测试集隔离、失败可追踪、产物可复核。涉及模型效果还需相应独立证据；外部数据/评审与平台权限未到位的条目记录具体阻碍，保持未完成。
