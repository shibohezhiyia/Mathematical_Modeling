# 神经 UDE 残差后端

项目现在提供一个可选的、预算受限的神经 UDE 残差后端：

\[
  f(x,u)=f_{known}(x,u;\theta)+g_{neural}(x,u;\phi).
\]

它不是题目专用求解器，也不把神经网络修正项解释成已证明的物理定律。后端只在调用者已经给出 `target_rhs`、`known_rhs` 和修正特征时执行；这一步刻意不替代题面变量角色和单位确认。

## 执行契约

`core.ude_neural.fit_neural_ude` 使用小型 MLP 学习残差，按时间顺序保留末段作为验证集。输入规模、网络宽度、训练轮数、重启次数和学习率都有硬上限；标准化统计量只从训练段计算。结果至少包括：

- 训练/留出行数与 RMSE；
- 纯已知机理在同一留出段的基线 RMSE；
- 多次重启的留出误差；
- 相对基线变化和明确的 `policy` 警告。
- 选中重启的网络结构、权重和训练段标准化统计量，可通过
  `core.ude_neural.predict_neural_ude` 在不重新训练的情况下复用；保存的权重只
  作为数值预测证据，不等同于物理参数或可辨识性证明。

缺少 PyTorch 时返回 `unavailable`，不会悄悄切换成另一种算法。神经后端的留出收益只能作为候选模型证据，不能单独证明可辨识性、守恒性或跨初值泛化。

调用者可以额外提交 `feature_domains` 以及 `target_dimensions`/`known_rhs_dimensions`。前者逐列检查输入是否位于声明域内，后两者必须完全一致才会标记量纲契约通过；任一项缺失时仍返回 `unit_status=not_assessed`。

## API 示例

```json
{
  "method": "ude_neural",
  "payload": {
    "target_rhs": [0.1, 0.2, 0.3],
    "known_rhs": [0.0, 0.1, 0.2],
    "correction_features": [[1.0], [2.0], [3.0]],
    "epochs": 100,
    "restarts": 2
  }
}
```

示例数据必须达到执行器的最小样本约束；上例仅展示字段形状。通过 `POST /api/research/external-method` 或内部运行时调用时，仍需经过统一方法路由和资源限制。

另有 `simulate_neural_ude_linear`：对小维度线性已知机制 `A x` 加逐状态残差网络，使用 RK4
在有界时间网格上闭环积分，并检查状态域、有限性和最大幅值。它把训练出的修正真正接入轨迹执行，
但仍不支持任意黑盒已知 RHS，也不能证明网络修正具有物理可辨识性。

新增 `fit_joint_neural_ude`：在同一条轨迹上联合优化线性机理矩阵 `A` 与神经残差，使用训练前缀
滚动拟合，并从初始状态滚动到未见后缀报告轨迹误差。该后端通过 `ude_joint` 运行时方法暴露，
只支持小维度 Euler 轨迹、严格预算和幅值护栏；它不是任意 UDE、刚性求解器或守恒结构的自动发现器。

新增 `simulate_neural_ude_stiff`：使用 SciPy `BDF` 或 `Radau` 对相同的线性+神经 RHS 做刚性意识积分，
记录求解器容差、函数评估次数并执行状态幅值护栏；运行时方法为 `ude_stiff`。这是真实的刚性后端，
但不会自动证明系统刚性、可辨识性或物理守恒。

## 尚未完成

当前实现是受限的“已知线性 RHS + 神经残差”轨迹后端，不是任意 ODE 积分器。跨初值/外部输入轨迹、梯度差分校验、可辨识性和与纯机理/黑箱的统一竞赛仍在路线图中，不能以当前接口宣称神经 UDE 已全部完成。
