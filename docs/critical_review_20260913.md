# 通用性、创新性与易用性评审及后续优化方案

评审日期：2026-09-13。依据：当前工作区代码、项目已有实验记录，以及 2023—2026 年相关论文。本文是定向文献对照与静态实现审查，不是穷尽性系统综述；没有重新运行已有基准、复现外部论文或开展真人可用性实验。文中的项目结果是已有记录，改善指标是拟议验收目标，不能当作已实现收益。

**1. 总体判断**

目前项目更接近“具有较丰富验证与审计设施的多方法建模研究原型”。现有证据尚不足以支持“通用、具有明确方法创新、普通用户可稳定使用的自动建模系统”。

最尖锐的问题是：**系统已经投入大量工作规定怎样才算正确，但在陌生任务上自动构造值得验证的模型，仍然是短板。能力清单的宽度超过了主流程的实际覆盖，可信度设施的完整程度超过了泛化证据的强度。**

这不是说现有工程没有价值。事实与假设分离、候选执行约束、反例重放、任务取消、独立确认和诚实状态，都是应当保留的基础。问题在于它们目前主要是工程资产，还没有形成一个被实验识别出来的研究贡献。

建议分清四个目标：通用性是同一机制能处理不同数学结构；普适性是换领域、数据来源、表达方式和运行条件后仍有可预测表现；创新性是相对既有方法具有可识别的新机制或新证据；易用性是用户无需理解系统内部结构也能完成任务。四者需要分别验收。

**3. 现有实验为什么撑不起定位**

[外部验证记录](D:/git/project/Mathematical_Modeling/examples/external_validation_20260911.json:1) 是六个公开案例的 Ridge—ExtraTrees 对比：平均相对 RMSE 变化约 -26.38%，精确双侧符号翻转检验 p=0.0625，Air Quality 退化约 2.25%。这是数据接入与预测评测链路的证据。

[系统比较记录](D:/git/project/Mathematical_Modeling/examples/system_comparison_20260911.json:1) 是 Ridge—当前 ModelingEngine：平均相对 RMSE 变化约 -23.79%，六个案例中有两个退化，约 +0.92% 和 +17.69%。它仍不等于升级前后完整研究助手的比较。两份实验的处理臂不同，不能混用其统计量。

六个案例还包含红、白葡萄酒这种相关来源，不能默认拥有六个完全独立领域。公开标签、独立评分进程和真正未见题盲评是不同概念。不同检验的区间或显著性结果应完整呈现，不能只挑有利的一项。

如果以“通用数学建模方法”投稿，我会给出重大修改意见：没有足够证据把收益归因于语义编译、结构搜索、修复或审计，而不是更强的表格预测器。若声称全面优于现有自动建模方法，当前证据无法接受。

真正的问题不是没有用上热门技术，而是**几乎每个计划中的单独卖点，都已有比“模块存在”更强的研究证据**。仅继续叠加这些技术，会扩大维护面，却不自动增加论文贡献。

**5. 建议收敛为一个可检验的研究问题**

推荐定位：**在题意有歧义、数据有限且预算受限时，自动选择澄清、补充证据、修复模型或停止输出的数学建模助手。** 首批明确支持代数关系和低维 ODE，再用约束优化验证架构能否迁移。通用预测服务可以保留为独立工具分支。

候选表示沿用现有 IR，但把题意解释、变量绑定、数学结构和适用范围关联起来。研究目标从“始终给出一个最好模型”，改为“在有限成本下减少有证据支持的决策错误，并识别信息不足”。

下一步动作允许：确认一个单位或变量角色、读取有权限的另一份观测、请求一个独立模拟/实验、修改一个结构子图、重新拟合、冻结确认、停止并说明未决条件。动作价值优先依据对任务损失的预期改善，再扣除计算、实验和人工交互成本；成本权重需要预先固定。概率无法校准时，先用候选集合的决策分歧或最坏情况收益做保守排序，不伪造后验。

例如，同样拟合现有数据的指数增长和饱和增长，可能给出完全不同的长期配置建议。有效下一步可能是确认观测时间单位，或获得一条较晚时期的独立观测；继续在原数据上调参可能毫无帮助。没有取得新证据时，输出条件化结论和分歧范围。

可争取的贡献是：语义解释与结构搜索的联合表示、不同证据动作的统一成本决策、事实不可变的修复机制，以及跨结构任务上的风险—覆盖—成本表现。**这是待验证的研究假设，不是已确认的原创点。** 必须与 LLM-AutoSciLab、LLM-ACES 等逐项比较，证明收益来自联合机制，而非换模型、更多查询或更保守拒答。

工程上有三项应随上述阶段推进：一是拆分基础安装与表格增强、深度学习、科学计算后端的可选依赖，并提供锁定环境与一键诊断；二是按输入绑定、执行编排、判决输出分离主助手职责，保留兼容入口；三是统一所有用户操作的任务状态、取消、重新计算和结果失效规则。不是为了减少文件行数而重写系统。

网页默认流程建议是“输入题目和附件 → 核对目标及必要绑定 → 显示首个有据结果与下一步”。结果首先说明建议、证据、适用范围与当前最关键缺口；IR、候选谱系和完整证书按需展开。已有图实验向导保留为专家模式，避免要求普通用户在研究助手、图实验和后端接口之间手工搬运状态。

**7. 验收必须怎样设计**

不能仅留出数据行。评测至少区分：相同结构的新样本、换单位和叙述后的同一问题、未见原语组合、不同领域来源、以及缺信息/矛盾条件/不可辨识任务。改写版本、不同随机种子、同一方程的参数实例按共同来源聚类，不能全部当作独立样本。

先用约 40—60 个独立来源或结构簇做开发试点，覆盖上述条件；最终确认集另行封存，规模由最小有意义效应、配对差异和风险精度要求决定。这个数量不是统计充分性的保证。公开竞赛题按来源和年份留出可测迁移，但无法保证模型预训练没有见过；公开变换基准、合成可判定任务和真正新题应分别报告。

对照分两层：整套系统比较“冻结旧版、升级版、相同 LLM 的普通工具调用流程”；专业能力比较“符号分支的 PySR/LLM-SR、主动采集分支的相关主动方法、表格分支的 CatBoost/LightGBM 及规模允许时的 TabPFN”。局部后端实验提供给定变量/单位的输入，端到端实验仍从原题与原表开始，避免把人工完成绑定后的成绩当作自动能力。

全部对照固定任务、模型版本、可见证据和预算，分别报告墙钟、求解评价次数、LLM token/API 费用、实验查询次数和人工时间。成熟方法的官方实现与项目内部同名适配器不能混为一谈；例如项目 `llm_sr` 分支实际执行类型化表达式/候选池搜索，不等于已经复现 LLM-SR 论文。

| 指标 | 定义或边界 | 拟议验收方式 |
| --- | --- | --- |
| 有效解率 | 通过独立任务评分的解数 / 全部入选任务，超时、失败和拒答留在分母 | 相对冻结旧版的配对改善；可先把 +10 个百分点作为试点目标，正式阈值在确认前冻结 |
| 已输出结论中的错误率 | 独立判定错误的已接受结论 / 全部已接受结论 | 与输出覆盖率联合报告，不能靠全部拒答获得低风险；示例目标为一侧 95% 上界不超过 5%，样本不够则标证据不足 |
| 表示稳定性 | 语义保持变换后，恢复到同一单位和变量空间的结论一致程度 | 确定性绑定应一致；随机搜索比较分布及预设容差，不能要求不同实现的公式文本完全相同 |
| 域外表现 | 未见结构、初值、驱动或来源上的误差、可行性与有效解率 | 按预登记子组报告，给出退化反例；不得只公布总体平均 |
| 人工负担 | 完成任务所需澄清轮次、专家介入时间、操作数 | 同等任务质量下比较；提问少但答错不算改善 |
| 易用性 | 新用户完成任务、理解限制和修改条件的成功率 | 先做 8—12 人的形成性测试定位问题，建议目标为约 80% 完成率；小样本只作设计反馈，不代表人群估计 |

最少做四组消融：去掉自动语义绑定、去掉结构修复、去掉动作价值策略、去掉证据门与停止策略。前两者检验泛化来源，第三项检验创新假设，第四项检验错误率控制的真实作用。去掉门控的版本仅用于离线评测。固定确认数据不得回流搜索；若最终确认促使修改系统，应使用新的确认集。

**8. 应暂停的工作与继续条件**

暂停以“扩大支持列表”为目的增加 PDE、GNN、NAS、RL 优化器和题目专用分支；除非失败分析显示明确需求。暂停新增与主流程脱节的审计包装和同义接口。每个新增模块必须说明它解决哪个已复现失败、如何进入主入口、在哪个同预算实验上验收。

继续投入的条件是：陌生结构任务的有效解率或人工负担出现可复查改善，且错误率没有被掩盖。若统一策略不能优于简单基线，就保留有效的工程改进，缩小科研主张。项目应首先证明“少量明确任务上，自动建模确实更可靠、更省人工”，再扩大通用范围。
